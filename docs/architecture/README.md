# 架构文档

按领域拆分,一个领域一个文件。这里没有"全局设计文档",因为一份所有 agent 都能改的大文档会迅速变得
无法审阅,也无法区分哪段还有效。

## 现有文档

| 文件 | 范围 |
| --- | --- |
| `mcp-surface.md` | AI 工具面的接口契约(第三阶段,未实现) |

采用模板时按你的真实领域建文件,例如 `identity.md`、`payments.md`、`web.md`。

## 写作规则

- 一个文件只描述一个领域的结构、边界和不变量。
- 跨领域的决策不写在这里,写成 `docs/decisions/` 下的 ADR,这里只引用它。
- 不复制代码里已有的细节。写"为什么这样分",而不是"这个函数做什么"。
- Agent 只修改自己这次变更真正触及的领域文件,见 `.ai/core/documentation.md`。

`scripts/ai-check` 会校验本目录下的相对链接是否指向真实文件。
