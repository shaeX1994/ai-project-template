# 0001. 用 ADR 记录架构决策

- Status: accepted
- Date: 2025-01-01
- Deciders: architect
- Supersedes: none

## 背景

Agent 和人都需要知道架构为什么是现在这个样子。单一的全局设计文档会迅速退化:每个 agent 都去改它,
diff 变得无法审阅,过期段落和现行段落无法区分。

## 决策

我们将把每一个改变服务边界、数据归属、通信方式或跨切面依赖的决策,记录为 `docs/decisions/` 下的编号 ADR。
ADR 只追加。过期的 ADR 由新 ADR supersede,而不是被修改。

## 后果

- 正面:决策历史可审阅;agent 可以引用决策,而不必从代码反推意图。
- 负面:每次架构变更多一个文件。
- 中性:架构文档拆成按领域的文件加一份决策日志。

## 考虑过的备选方案

| 方案 | 为什么不选 |
| --- | --- |
| 单一 `ARCHITECTURE.md` | 变成合并冲突集中地,且掩盖内容过期 |
| 仓库外的 wiki | 与代码漂移,无法在同一次变更里审阅 |
